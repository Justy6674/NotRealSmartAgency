## Problem Statement

Every time a business is added to NotRealSmart, the Director is supposed to already know the website, sitemap, branding, logo, GitHub, connections, and (if healthcare) the legal rules. Today that knowledge is optional. Some rows look complete and still have unread GitHub. A new business can be advised on with an empty kit. Justin asked for one file that tells every AI what to scan, what to link, and what not to invent — for new businesses and for the ones already in the account.

## Status Quo

The pipelines already exist and are not wired as a mandatory checklist:

- Website scan + screenshot: `scanWebsiteCore` in `src/lib/agents/tools/scan-website.ts`
- Sitemap: `discoverWebsiteSitemap` from `runProjectDiscovery`
- Brand kit (CSS colours, fonts, voice from the page): `extractBrandKitCore`
- GitHub App bind + `github_context`: `runProjectDiscovery` in `src/lib/discovery/project-discovery-run.ts`
- Catch-up script: `scripts/setup-projects.ts` (idempotent; needs production GitHub App env)
- Health rules injected when flags are on: `getComplianceRules` in `src/lib/agents/prompt-builder.ts:229`
- Blogging health handover: `src/lib/blogging/health-checklist.ts`
- Publish/save gates already fail closed

Status quo cost: the Director invents or stays silent; Git is linked as a URL and never read; a health business can be talked about without the flag if someone guesses from the name.

## Target User & Narrowest Wedge

Users: Justin and Bec. Non-technical. Australian English. They talk to the Director.

Wedge this week: one operational contract file (`NRS.md`) plus the existing catch-up script so every current business gets GitHub + sitemap the same way a new one would. Not a wizard. Not a video editor. Not a blog CMS.

## Constraints

- Do not implement the onboarding machine, blog CMS bridge, or video editor in this pass
- Do not reverse copy-paste blogging or Social compose (Save draft / Pick a time / Next free slot / Post now)
- Do not show Mixpost / OAuth / Zernio / AbeAI names in the UI
- Do not apply_migration, billing, homepage, or other-repo pushes
- Zernio does not isolate tenants; NRS filters after `normaliseAccount`
- Health injection reads `compliance_flags`, never the brand name
- Build-First: wrap FireRed or lossless-cut only as a last resort

## Premises

- A contract the Director and coding AIs both follow beats a new onboarding product
- Hollow GitHub context is the live gap; palettes are no longer the gap
- EndorseMe already has a draft-only intake; NRS does not call it yet
- Video “editor” demand from the wife is trim-and-post, which `tighten-video` already does in code
- Using more of Zernio is safe only behind `publishToPlatform` and only after account IDs are stored per customer

## Approaches Considered

### Approach A: Build the full onboarding machine now

Website crawl, Git connect, logo scrape, health injection, EndorseMe blog write path, FireRed or lossless-cut editor, and every Zernio endpoint. Rejected: platform vision. The tools exist; the checklist does not. Shipping all of it would bury the GitHub catch-up that actually hurts today.

### Approach B: Contract file + one catch-up slice

Write `NRS.md` as the operational checklist. Next engineering click is run (or expose) `scripts/setup-projects.ts` so current brands get the same GitHub + sitemap pass. Later slices: EndorseMe draft handoff from NRS, trim-in-compose, Zernio webhooks/queue/customContent.

## Recommended Approach

Approach B. `NRS.md` is the artifact Justin asked for. It is not a manifesto. It is the missing gate in front of pipelines that already exist.

- Every current business has `github_context` or an explicit “no repo / App cannot see it” note
- A new business cannot be advised on until the checklist in `NRS.md` has run or been marked unavailable
- Health rules appear only when the flag is on
- Blogging still never publishes to their website
- No vendor names in the UI
